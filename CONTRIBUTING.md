# Contributing

Contributions are highly welcome! Be it bug reports, feature requests or PRs. However, please keep a bunch of "rules" in mind when wanting to contribute.

## No pressure, please
Please don't set your expectations too high or put any pressure. This project is for free and built for fun and out of passion. **Please be kind**, respectful and do not _demand_ anything by any means when requesting new features.

## Accept rejects
Be indulgent if your feature request or PR gets rejected. While we're open for suggestions of all kinds, this project is ultimately maintained by @muety, @tldev-de and @fotofiete as the authors and core contributors. Even if a feature- or change request may objectively be sensible, we still reserve to have the final say (sorry :v:).

## Ask first, then code
Please do not submit a PR out of the blue. Before submitting a PR and requesting a review, please file an issue first and spark a discussion about your intended change. If you intend to submit a PR for an already existing issue (feature request or bug), please still leave a comment in that issue first to signal your interest for implementing it. It's not uncommon that issue, despite being still open, have become obsolete in the meanwhile, and you shouldn't be wasting your time with something that's potentially not of need anymore.

## AI-generated code
Please do not submit purely AI-generated code. We expect contributions to be either entirely "hand-written" or at least thoroughly reviewed when implemented in collaboration with AI. Letting some LLM run over the code base and then blindly submitting its output is not the point of open source in our opinion. We'd rather want contributors to spend time familiarizing themselves with the code base, try to wrap their heads around how things work under the hood and then start coding.

**Happy coding! :nerd_face:**
